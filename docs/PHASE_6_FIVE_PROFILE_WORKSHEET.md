# Phase 6: five independently labelled profiles

Status: **not authored or labelled yet**. This is a worksheet, not an evaluation dataset. The maintainer supplies five synthetic or anonymised cases and expected outcomes from cited sources before seeing engine output. No model-written case or label may be marked human-authored. Keep real identifying details out of the repository.

Use [the coverage matrix](PHASE_6_RULE_COVERAGE.md) and official evidence. Choose realistic cases spanning a met numeric boundary, a shortfall, missing facts, and an alternative or exemption. Cases can include university-review outcomes. These are coverage suggestions, not assigned expected labels. Each case targets one exact covered slug; variants must identify their shared base case.

The profile schema arrives in Step 1. Plain-language facts can be recorded now and mapped to that schema without changing their meaning or expected labels. Leave unknown facts blank, explicitly distinguish none from not supplied, and record credits/grade/test units and versions. The request owns Germany, target, intake, starting year and the fixed `as_of` date.

For each expected criterion, record requirement, entered fact, applicability, verdict, margin if comparable, citation and rationale. Criterion labels are `meets`, `does_not_meet`, `unknown`, `not_published`. Headlines are `meets_checked_published_requirements`, `does_not_meet_published_requirements`, `needs_information_or_review`, or `not_covered`. Keep academic, document/deadline readiness and finance outcomes separate. A university-review judgment is not a numeric failure.

Freeze each label set with an authorship note and date before the first engine run. If a disagreement later reveals a source error or ambiguous interpretation, preserve the original label and record the reviewed change and reason. The five cases are reported separately from the 35 assisted cases; a shared implementation and label author is not independent evidence.
