# CLAUDE.md

Local-only file (gitignored). Guidance for working in this repository.

## 1. Project in one paragraph

An admissions and eligibility assistant for international students applying to **English-taught master's programmes in Germany** (CS, Data Science, AI). For each programme a student gets a cited eligibility and gap report (meets / does not meet / missing info, with margins, never an admission probability), the visa, funds and arrival rules that apply, and a chat that cites official pages. Built on a hand-written hybrid RAG core (FastAPI backend + React/Vite frontend). Germany only (UK/US dropped 2026-10-06). The repo was EngineerDoc AI until 2026-10-04.

**Goal of the build (maintainer):** deploy as soon as possible and use it on a CV as proof of real GenAI / RAG / LLM-systems skills, without lowering data quality. A reviewer should see: a live URL, a README with real eval numbers and an architecture diagram, a CI eval gate, an agent and an MCP server. The maintainer must be able to defend every design choice in an interview.

**Interview one-liner:** "A hybrid-RAG and rules-engine system. The LLM extracts, plans and explains; retrieval and a deterministic engine supply the facts and decisions."

## 2. Non-negotiables

1. **The LLM never decides eligibility.** It extracts and explains; a deterministic rules engine decides.
2. **Every requirement field is cited** (verbatim quote + doc id) and passes the quote-in-page check. Each verified record carries a `tier`: `human` (every field ticked in `make review`; 6 programmes) or `second_pass` (re-read against the cited pages and saved through the Save path, not hand-ticked; 7 programmes, checked by a seeded sampled audit). Never describe a `second_pass` record as hand-verified; promotion to `human` is a deliberate hand edit.
3. **No LangChain / LlamaIndex.** Retrieval modules are hand-written; the LLM SDK is used directly through one thin client.
4. **Every feature leaves a runnable test or check.**
5. **No real personal profiles** through the free-tier LLM (the provider may use prompts).
6. **No AI attribution anywhere** committed (see section 4).

## 3. Start of every session

1. Read `STATUS.md` (local handoff: Now, Next, dated Log).
2. Read `docs/PROJECT_PLAN.md` before starting or continuing a phase. It holds the scope, phases, phase order and each phase's "Done when" line.
3. `LEARNING.md` holds each phase's notes, quiz questions and owed DECISIONS entries. `DECISIONS.md` is owned by the maintainer: entries are drafted from the decisions taken in working sessions (STATUS log, LEARNING, plan), dated on the day decided, append-only (a superseded entry gets an "Updated <date>: ..." line, never an edit), then read and edited by the maintainer into their own words. Tick the matching box in LEARNING when a draft is written. `REVIEW_AND_FINALIZATION_PLAN.md` (local) is superseded; its live items are in section 8 of the plan.

At the end of every session and at every "Commit Phase N": update `STATUS.md` (rewrite Now and Next, add one Log line). A phase starts only when the previous one meets its "Done when" line and is committed.

## 4. Working rules

- **No AI attribution anywhere.** No `Co-Authored-By` trailers, no "generated by" lines, no mentions of AI coding tools (including the cross-checker) in commit messages, PR descriptions, code, comments or committed docs. Committed docs call it "the second-model cross-check". Commits are authored by the repo owner only.
- **Commit messages:** conventional (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`), short imperative subject (~70 chars), optional bullet body in plain wording.
- **Publish rule (before every commit or push).** The GitHub repo is the portfolio: publish only what a reviewer needs to understand, run or verify the product (code, tests, verified data, eval numbers, architecture and spec docs, README). Everything that only helps us build is gitignored, never committed: worksheets and decision/review sheets addressed to the maintainer (`docs/working/`), audit sheets, `STATUS.md`, `CLAUDE.md`, caches, crawled pages, indexes, tool output. For each staged path ask: does a reviewer need this? If not, add it to `.gitignore` instead. Run `make check-publish` (staged paths and blocked phrases) and read `git diff --cached --stat` before committing; no AI attribution, no "you answer" sheets. New working paper -> `docs/working/`. Repeat the check before opening a PR or making the repo public.
- **Tests and settings.** `get_settings()` is a cached shared object: tests never mutate it. Tests that change paths use `load_settings()` (fresh copy) or `monkeypatch`. Run the whole CI test list together before committing, not just the new file.
- **Git flow:** one branch and one PR per phase (`phase-N-short-name`). `gh` is authenticated; pushing branches and opening PRs is allowed. Do not merge unless asked. Never force-push `main`. Stage files explicitly; never `git add -A`. Check `gh repo view --json visibility` before any push; the repo stays private until the maintainer says it goes public.
- **Secrets:** keys live in `.env` only (gitignored); `.env.example` holds empty values. The key is `GEMINI_API_KEY`. Never ask for or echo a key.
- **Phase loop:** "Start Phase N" -> short brief; build in small steps, each with a test or check; the maintainer does the hands-on task; "Explain Phase N"; append notes, quiz questions and owed DECISIONS entries to `LEARNING.md`; "Commit Phase N". Quizzes are batched after Phase 10; DECISIONS entries are drafted per phase and edited by the maintainer. Neither gates a phase. Other commands: "Status?", "Pause, explain why X", "I disagree with X because Y".
- **Explain, don't silently decide.** Push-back is welcome. Give a recommendation, not a survey.

## 6. Scope and data

- **Pilot (Phase 2):** TUM, RWTH Aachen, TU Berlin, Saarland, TU Dresden: 8 programmes.
- **Batch 2 (end of Phase 3):** KIT (CS, Computational and Data Science), TU Darmstadt (CS, AI and Machine Learning), University of Stuttgart (CS; its AI/DS master's is German-taught). LMU, Bonn, Tübingen, Mannheim were cut on 2026-10-13 to ship sooner.
- **Total: 8 universities, 13 programmes, 72 registry sources** (as of 2026-10-16). `sources/registry.yaml` is the authoritative list.
- **Long tail:** data-only work after deploy (registry, crawl, extract, check, verify). No code changes.
- Coverage behaviour: country rules answer for any German university; the verified report covers only registry programmes; an uncovered university gets "not covered yet" + country rules + DAAD link + paste-text unverified check; another country gets "Germany only" + the official portal link.

### Registry id conventions
`de/<uni-code>/<programme-code>/<page>` for programme pages, `de/<uni-code>/<page>` for uni-wide pages, `de/<city>/<page>` for city pages, `de/rules/...`, `de/scholarship/...`. Uni codes: `tum`, `rwth`, `tub`, `saarland`, `tud` (Dresden), `kit`, `tu-darmstadt`, `ustutt`. `--only` filters by id **prefix**, so no code may be a prefix of another (`tud` vs `tuda` is why Darmstadt is `tu-darmstadt`).

## 7. LLM provider

Gemini free tier through its OpenAI-compatible endpoint, using the OpenAI SDK in `generation/llm_client.py` (the only module that touches the SDK). `models.llm_base_url`, `models.llm_model` (default `gemini-3.8-flash`) and `models.llm_fallback_models` (`gemini-3.6-flash`, `gemini-3.5-flash`; a 429 moves to the next) live in `config/settings.yaml`. `gemini-2.5-flash` is closed to new keys.

- **Quota: about 20 requests/day per model**, each model counted separately. ~1 min per extraction call; `extraction.delay_seconds: 30` avoids the per-minute limit; 503 overloads happen. Failed programmes are skipped; re-running `make extract` fills only the gaps.
- `tests/conftest.py` blanks the key so tests never call the API. With no key, the extractive fallback keeps the app working.
- No Anthropic API budget. The second-model cross-check runs inside Claude Code (subagents reading local files), not through an API.

## 8. Commands

All Python Makefile targets call `.venv/bin/python` directly; no activation needed.

```bash
make install     # create .venv, pip install -e '.[dev]'
make crawl       # registry -> data/raw/ + sources/manifest.json (the only network step)
                 #   cached sources skipped; ARGS="--refresh" re-fetches; ARGS="--only de/kit" filters by id prefix
make ingest      # registry + manifest + data/raw -> data/processed/chunks.jsonl
make index       # dense (.npz) + BM25 indexes in data/index/
make extract     # LLM -> data/extracted/<slug>.json (needs GEMINI_API_KEY)
                 #   existing drafts skipped; ARGS="--refresh --only tum" (slug substring); bad quotes dropped
make review      # review screen at http://127.0.0.1:8001 -> data/verified/<slug>.json
make eval        # validate_gold.py, then 4-way benchmark -> frontend/public/benchmark.json + README table
make test        # pytest -q
make run         # uvicorn api.main:app --port 8000
make fmt         # ruff format .
make eligibility ARGS="--profile p.json --programme <slug> [--as-of YYYY-MM-DD --intake winter|summer --starting-year YYYY]"   # report
make eval-eligibility [ARGS="--cases f.jsonl --out f.json"]   # validate + run eligibility cases -> evaluation/results/eligibility_baseline.json (exit 1 if missing/invalid)
make eligibility ARGS="--validate"                # rule files bound to records, quotes in record (cache where data/raw exists)
make eligibility ARGS="--validate --check-cache"  # a missing cached page is an error (local, needs data/raw)
make validate-phase6-inventory [ARGS="--check-cache"]   # Step 0 inventory and Phase 4 hashes
make check-publish  # publish rule on staged paths and phrases

.venv/bin/python scripts/dump_pages.py [slug-filter]   # data/pages/<slug>/ for the cross-checker
.venv/bin/python scripts/validate_gold.py [file]      # gold-set label check (make eval runs it first); exit 1 on any problem
.venv/bin/python scripts/audit_sample.py [n] [seed] [--sheet]   # seeded sample of second_pass stated fields; --sheet -> data/audit/audit_sheet.md (used: 35 4)
.venv/bin/python -c "from core.config import get_settings; from evaluation.extraction_eval import render; print(render(get_settings()))"   # extraction accuracy table
.venv/bin/python -m pytest tests/test_rrf.py -q        # single file

cd frontend && npm install && npm run dev    # :5173; `npm run build` = tsc + vite build
```

- Order: `crawl` -> `ingest` -> `index` -> `extract` -> cross-check -> `review`. `ingest`, `index` and `review` are offline.
- Registry change -> `make crawl` first. Chunking or embedding change -> `make ingest && make index`.
- Tests never touch the network or the real corpus: `tests/conftest.py` points settings at `tests/fixtures/` and writes to temp paths. `test_api_smoke.py` / `test_e2e.py` build real indexes (first run downloads bge-small ~130MB and bge-reranker-base ~1.1GB).
- `frontend/public/benchmark.json` and the README block between `<!-- BENCHMARK:START/END -->` are overwritten by `make eval`.
- CI: `.github/workflows/ci.yml`.

## 9. Architecture

### Built

Data flow: **registry** -> **crawl** -> raw cache + manifest -> **ingestion** -> `chunks.jsonl` -> **indexes** -> **retrieval** -> **generation** -> **API / frontend**. In parallel: raw pages -> **extraction** -> drafts -> **cross-check** -> **review** -> verified records.

- `ingestion/registry.py`: pydantic-validated registry (`id`, `url`, `country`, `layer` rules|scholarship|university, optional `stage` before_applying|visa_document|visa_funds|arrival|after_graduation, `university`, `programme`, `title`). Duplicate ids fail. City pages carry the university whose city they cover.
- `ingestion/crawler.py`: `crawl` is the only network code (robots.txt fail-closed on unreachable/401/403/5xx, per-host delay with robots Crawl-delay, size cap, redirect tracking, manifest record with sha256/changed/error; a failed fetch keeps the previous raw file). `load_corpus` is offline and joins registry + manifest + raw.
- `ingestion/pipeline.py`: parser (BeautifulSoup; pdfplumber with tables as markdown, page cap) -> cleaner -> structure-aware chunker (headings, never inside fenced code, whitespace proxy + real-tokenizer second pass at `chunking.model_token_limit`, ~12% overlap). Provenance copied onto every `Chunk` (`schemas/common.py`).
- `retrieval/pipeline.py`: `RetrievalPipeline.search(query, mode, top_k, timer)` with `vector`, `bm25`, `hybrid` (RRF) and `hybrid_rerank` (cross-encoder over top `rerank_n`). Each `RetrievedChunk` carries all scores. `build_indexes` lives here. `vector_store.py`: NumPy default, Qdrant optional. BM25 in-process with an identifier-aware tokenizer.
- `generation/answer_generator.py`: refusal gate on sigmoid(top rerank logit) vs `generation.refusal_threshold`; LLM path with a key, extractive fallback without; shared `[n]` numbering and `citation_mapper.map_citations`.
- `extraction/schemas.py`: `ProgramRequirements` with 17 `Cited[T]` fields (status stated|not_published, value, verbatim quote, doc_id): degree, ECTS, subject credits, German-scale and original-scale grade minimums, English tests, entrance tests (GRE/GATE with applies-to and exempt degree-country lists), German level, work experience, APS degree countries, application route, deadlines, selection process, documents, non-EU tuition, semester fee, language of instruction. Test-name aliases normalise GRE/GATE/TOEFL spellings.
- `extraction/extract.py`: `collect_sources` gives each programme its own pages plus its university's programme-less `university`-layer pages (city/rules pages are excluded). One JSON-mode call per programme, pydantic validation, one repair retry, `check_quotes` drops fields whose quote (word-normalised, >= `min_quote_words`) is not in the cited page.
- `extraction/review.py` + `review.html` (`make review`, separate app from `api/`): field next to quote and full page text; automatic warnings (numbers in value not in quote; not_published fields whose keywords appear on the page); cross-check verdict per field from `data/checked/` (green = agrees and no warning, amber otherwise); a suggestion must pass the same schema + quote check or it is marked invalid. Every field must be ticked; Save re-checks quotes and writes `data/verified/` with a `tier` (`human` by default; a re-save keeps the existing tier, so `second_pass` records stay `second_pass` until promoted by hand).
- `api/`: `create_app()` wires request-id -> logging middleware, CORS (hard-coded to localhost:5173; must become configurable before deploy), routers `search`, `answer`, `ingest`, `evaluate`, `health`. `dependencies.py` caches pipeline and LLM client. Per-stage latency via `core.metrics.StageTimer`.
- `evaluation/runner.run_benchmark`: four modes, Recall@k, MRR, nDCG, p50/p95, token-overlap groundedness heuristic. Gold labels are doc-level with optional section substrings.
- `evaluation/retrieval_eval.GoldItem`: optional `kind` (requirement | country_rules | confusable | multi_hop | refusal | coverage), `university`, `programme`, `author` and `reviewed_by` (model | human), `expect_refusal`; all defaulted. Gold set: `evaluation/datasets/gold_qa.jsonl` (104 items, all model/model, human review pending; review record in `gold_review.md`). Refusal/coverage items have no doc ids and are skipped by retrieval metrics.
- `evaluation/extraction_eval.py`: draft vs verified per field (unchanged only if status, value, quote and doc_id all match), plus checker precision/recall from `data/checked/`. Headline on the `human` tier (6 programmes, 102 fields, 0.794 unchanged); the second_pass tier is not independent of the cross-check.
- `scripts/audit_sample.py`: seeded sample of `stated` fields from `second_pass` records; `--sheet` writes `data/audit/audit_sheet.md` (35 of 69, seed 4; model pre-check 33 agree, 2 disagree; human audit pending, result to `data/audit/second_pass_audit.json`).
- `frontend/`: Search tab (`POST /answer`) and Dashboard tab (static `/benchmark.json`).

### Cross-check procedure (Phase 3, run by Claude Code, not by the maintainer)
1. `scripts/dump_pages.py <slug>` writes the exact text the quote check uses.
2. One subagent per programme reads `data/extracted/<slug>.json` + `data/pages/<slug>/` and writes `data/checked/<slug>.json`: `{slug, checked_at, fields: {<field>: {verdict, value, quote, doc_id, reason}}}`, verdict in correct | wrong | partial | missed | not_published_ok | unsure. Pages only, no outside knowledge, quotes character for character, "unsure" over guessing, numbers and country lists checked digit by digit.
3. Spot-check the first programme's wrong/partial/missed claims by hand before trusting the batch.
4. A checked file is only valid for the draft it checked: re-run the check after any `make extract --refresh`.

## 10. Configuration

`config/settings.yaml` is the single source of truth (paths, crawl, chunking, retrieval, models, extraction, generation, evaluation), loaded into pydantic models in `core/config.py` (`get_settings()` is `lru_cache`d). Env overrides: `QDRANT_URL`, `VECTOR_BACKEND`, `EMBED_MODEL`, `RERANK_MODEL`, `LLM_MODEL`, `GEMINI_API_KEY`. No magic numbers: add a field to the right `*Cfg` class and the yaml.
